Rimay Quantum Feature Extraction — Qiskit Function від Kipu Quantum

Див. довідник API.

примітка

Qiskit Functions — це експериментальна функція, доступна лише користувачам IBM Quantum® Premium Plan, Flex Plan та On-Prem (через IBM Quantum Platform API) Plan. Вони перебувають у статусі попереднього випуску і можуть змінюватися.

Огляд​

Rimay доповнює класичні конвеєри машинного навчання ознаками, згенерованими на квантовому обладнанні. Функція приймає класичні табличні дані та повертає набір квантово перетворених ознак. Коли квантова система обробляє дані, вона генерує багаті ознаки, що відображають нелінійні зв'язки між вхідними даними. Ти можеш використовувати згенеровані ознаки окремо або разом з початковими ознаками для навчання будь-якої класичної моделі. На малих і середніх наборах даних квантово перетворені ознаки можуть покращити якість прогнозування порівняно з суто класичними базовими моделями.

Ця функція створена для таких користувачів:

  • Команди з науки про дані, які мають наявний конвеєр машинного навчання на малих і середніх табличних наборах даних, де якість прогнозування досягла плато. Ти додаєш Rimay як один додатковий крок попередньої обробки, не будуючи жодних квантових схем самостійно.

  • Дослідники, які вивчають квантові методи для задач машинного навчання.

Опис​

Алгоритм квантового вилучення ознак [1] поєднує два принципи квантового машинного навчання. Перший — квантові карти ознак, які вбудовують дані у високовимірний гільбертів простір і тому дають виразніші представлення. Другий — квантові обчислення на резервуарі, які використовують динаміку квантової багаточастинкової системи як нелінійне перетворення вхідних даних.

Rimay кодує значення ознак і взаємну інформацію між ознаками в локальні поля та коефіцієнти зв'язку гамільтоніана спінового скла. Контрдіабатична квантова динаміка еволюціонує систему до її низькоенергетичних станів, які містять нелінійні суміші кореляцій у вхідних даних. Rimay вилучає ці кореляції, вимірюючи одно- та двочастинкові середні значення. Ці середні значення — це квантово перетворені ознаки, які ти подаєш у свою модель машинного навчання.

Робочий процес​

  1. Попередньо обробити табличні дані так, як ти робиш для класичного машинного навчання. Rimay потребує числових ознак, тож перетвори категоріальні ознаки на числові, наприклад за допомогою OneHotEncoder зі scikit-learn.

  2. Розділи дані на навчальну та тестову вибірки й завантаж обидві у функцію, як показано в розділі Приклад.

  3. Rimay використовує навчальні дані, щоб побудувати гамільтоніан, який представляє дані. Кожна ознака відповідає одному кубіту, а повна навчальна вибірка визначає, які ознаки, а отже й кубіти, взаємодіють. Rimay зберігає цю структуру, щоб відображати тестові та пізніші дані для виведення за допомогою того самого гамільтоніана.

  4. Для кожного зразка значення ознак задають локальні поля гамільтоніана, а взаємна інформація між ознаками задає коефіцієнти зв'язку структури з кроку 3. Rimay дигіталізує контрдіабатичну еволюцію цього гамільтоніана в схему й запускає схеми на QPU.

  5. Rimay вимірює отримані бітові рядки, а потім обчислює одночастинкові середні значення та двочастинкові середні значення фізично зв'язаних кубітів.

  6. Ти завантажуєш середні значення у вигляді, який можна подати безпосередньо у свою модель або об'єднати з початковими ознаками.

примітка

Через таку структуру кількість кубітів, потрібних для запуску, дорівнює кількості ознак, а кількість схем, які він надсилає, дорівнює кількості зразків.

Після підгонки відображення ти можеш пропускати через нього нові дані, наприклад для виведення. Тоді Rimay отримує гамільтоніан, створений під час підгонки, і будує з нього схеми для нових зразків.

Інтегруй Rimay у свій конвеєр машинного навчання​

Як і в класичному конвеєрі, ти починаєш з попередньої обробки необроблених даних, наприклад за допомогою one-hot кодування категоріальних ознак, і розділяєш їх на навчальну та тестову вибірки. Замість того щоб подавати обидві вибірки безпосередньо у свою модель, ти спершу подаєш їх у Rimay і навчаєш модель на квантово перетворених ознаках.

Бенчмарки​

Kipu Quantum протестувала Rimay на наборі даних German credit з OpenML [2], який класифікує 1000 кредитних заявників як добрих або поганих кредитних ризиків. Він має 13 категоріальних і сім числових атрибутів. One-hot кодування категоріальних атрибутів дає 48 числових ознак. У бенчмарку 20% зразків відкладено як тестову вибірку.

Як базову лінію було навчено кілька класичних моделей на класичних ознаках. З Rimay випадковий ліс навчали двома способами: лише на квантово перетворених ознаках (Random forest Q) і на квантово перетворених ознаках, об'єднаних з класичними (Random forest H, від hybrid). У таблиці наведено лише випадковий ліс, бо він показав найкращий результат на квантово перетворених ознаках.

обережно

Тестова вибірка містить лише 200 зразків, тож один додатково правильно передбачений зразок змінює точність на 0.005. Сприймай ці відмінності як тенденцію, що потребує подальшої перевірки, а не як значущий ефект. Точність прогнозування також може залежати від спричиненого обладнанням шуму у вилучених ознаках. Тому використовуй достатньо shots, щоб шум вибірки не обмежував результат.

Вхідні дані​

mode визначає, які параметри потрібні для запуску. Опис кожного вхідного параметра див. у довіднику API.

Вхідні файли​

  • Завантаж кожен файл за допомогою catalog.file_upload() перед запуском функції.

  • Завантаження замінює будь-який раніший файл з тією самою назвою, навіть для завдання, яке ти надіслав, але яке ще не почалося. Щоб запускати кілька завдань одночасно, дай файлам кожного завдання власні назви, наприклад run1_x_train.csv і run2_x_train.csv.

  • Кожен файл — це файл CSV із рядком заголовка. Кожен стовпець файлу ознак — це одна ознака, і кожне значення має бути числовим.

  • y_train містить рівно один числовий стовпець, з однією міткою на рядок x_train. Перетвори категоріальні мітки на числа, наприклад good і bad на 1 і 0.

  • x_test і x_inference повинні мати ті самі стовпці, що й x_train, в тому самому порядку.

Збережи mapping_id і backend_name

mapping_id — єдиний спосіб дістатися до відображення, створеного підгонкою, і його не можна знайти чи відновити. Він авторизує використання цього відображення, тож став до нього як до облікових даних і не поширюй. Якщо ти його втратиш, доведеться підганяти нове відображення, що коштує ще одного запуску на квантовому обладнанні. Також запиши backend_name підгонки, бо відображення працює лише на цьому процесорі.

Обмеження​

  • Кожна ознака відображається на один кубіт, тож процесор повинен мати щонайменше стільки кубітів, скільки ознак у твоїх даних. Якщо ознак більше, спершу зменш їх технікою відбору ознак.

  • Кожен зразок стає однією схемою, а запуск враховує навчальні й тестові зразки разом. Запуск може містити щонайбільше 15 000 зразків.

  • Одне завдання може запросити щонайбільше 10 мільйонів виконань, тож кількість зразків, помножена на shots, не повинна перевищувати 10 мільйонів.

  • Завдання має завершитися протягом 24 годин, включно з часом очікування його схем у черзі процесора. Завдання, яке триває довше, зупиняється без результату. На завантаженому процесорі тримай великі набори даних значно нижче цих обмежень.

Вихідні дані​

job.result() повертає словник. Самі квантово перетворені ознаки записуються у файли CSV, які ти завантажуєш за допомогою catalog.file_download(). Опис кожного ключа словника див. у довіднику API. Час, який забрала кожна фаза виконання, див. у розділі Метадані запуску.

Кожен вихідний файл містить один рядок на кожен вхідний рядок, у порядку вхідного файлу, і один стовпець на кожну квантово перетворену ознаку. Стовпці, назви яких починаються з corr_, — це двочастинкові середні значення. Файли не містять стовпця міток. Мітки твоїх навчальних даних залишаються у твоєму файлі y_train.

Метадані запуску​

resource_usage містить один запис для кожної фази виконання, яку пройшов запуск: "RUNNING: MAPPING", "RUNNING: POST_PROCESSING" і, на QPU, зазвичай "RUNNING: WAITING_FOR_QPU". Кожен запис містить CPU_TIME, астрономічний час фази в секундах, і QPU_TIME, час QPU в секундах. На QPU час QPU, виставлений IBM до оплати, записується під "RUNNING: MAPPING", фазою, у якій виконувалися схеми.

"RUNNING: WAITING_FOR_QPU" — це час, який твої завдання чекали в черзі IBM. Запуск бере цей час із міток часу завдань IBM і не враховує його в "RUNNING: MAPPING". Якщо IBM не повідомляє ці мітки часу для кожного завдання, запис відсутній, а очікування входить до "RUNNING: MAPPING".

IBM® завершує обчислення використання через деякий час після завершення завдання. Запуск чекає на нього до приблизно хвилини. Використання, яке ще обчислюється після цього часу, не включається в QPU_TIME, а остаточне використання показано на IBM Quantum Platform. Якщо запуск не може прочитати використання від IBM, QPU_TIME дорівнює None.

Наприклад:

"metadata": {
    "version": "0.3.0",
    "resource_usage": {
        "RUNNING: MAPPING": {"CPU_TIME": 12.4, "QPU_TIME": 6.0},
        "RUNNING: WAITING_FOR_QPU": {"CPU_TIME": 28.8, "QPU_TIME": 0.0},
        "RUNNING: POST_PROCESSING": {"CPU_TIME": 0.3, "QPU_TIME": 0.0},
    },
}

Розміри функції​

Кожне завдання виконується з одним розміром — S, M або L. Якщо вказаний розмір замалий, завдання відхиляється. Якщо розмір більший, ніж потрібно, завдання виконується на більшому обчислювальному профілі, ніж вимагає робота.

Розмір завдання Rimay залежить від кількості зразків, які воно відображає: рядки x_train і x_test для fit-transform та рядки x_inference для transform. Мітки в y_train не враховуються, а запуск delete не відображає жодних зразків.

РозмірЗразків на завданняОбчислювальний профільvCPURAM
SДо 2 9998x32832 ГБ
MВід 3 000 до 9 9998x32832 ГБ
LВід 10 000 до 15 00016x12816128 ГБ

Кількість зразків — єдиний критерій. Розмір змінює лише обчислювальний профіль: обмеження на ознаки, зразки та shots однакові для кожного розміру. S і M виконуються на одному обчислювальному профілі та відрізняються кількістю зразків, яку кожен охоплює.

Типовий розмір — M, він використовується, коли завдання не запитує розмір. Тому завдання з понад 9 999 зразками має запитати L.

Ти також можеш прочитати відповідність із самої функції через rimay.sizes_map, а розмір, з яким виконується завдання, коли воно його не запитує, — через rimay.default_size.

Обчисли розмір перед надсиланням​

Запусти це на власних вхідних даних. Воно лише читає їх і більше нічого не робить: жодне завдання не надсилається і нічого не резервується, тож можеш викликати його скільки завгодно разів.

Передай самі набори даних, а не назви їхніх файлів, у тому самому порядку, що й input_file, разом із mode запуску. Крок 2 прикладу показує виклик.

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

Якщо розмір замалий, завдання завершується з помилкою 4600, і повідомлення називає розмір, який слід використати натомість. Якщо він більший, ніж потрібно, завдання виконується нормально і записує подію-повідомлення 4601.

4. Відобрази нові дані​

Після навчання моделі відобрази нові дані за допомогою підігнаного відображення, наприклад для виведення. Цей приклад відображає x_inference.csv, який записала перша комірка цього прикладу. 5. Видали відображення​

Коли підігнане відображення тобі більше не потрібне, видали його. Запуск delete не виконує жодної квантової роботи, тому не потребує ні процесора, ні shots, ні розміру функції.
