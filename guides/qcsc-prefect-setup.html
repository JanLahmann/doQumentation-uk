Налаштування QCSC-Prefect на кластері Slurm

Цей посібник готує вхідний вузол (login node) кластера Slurm як хост робочих процесів qcsc-prefect. Навчальний матеріал із qcsc-prefect SQD починається з результату цього посібника.

Після завершення цього посібника ти матимеш такі елементи:

ЕлементДеВміст
~/venv/qcsc-hostВхідний вузол, хост робочих процесівPrefect, пакети qcsc-prefect і команда qcsc-qrmi
~/venv/qcsc-nodeОбчислювальні вузли, всередині завдань SlurmВоркер QRMI: QRMI з його командою task_runner і qcsc-prefect-qiskit
qrmi-runtimePrefectБлок, що називає твій екземпляр IBM Quantum® і QPU
qrmi_config.jsonВхідний вузол і обчислювальні вузлиТвій ключ API IBM Cloud®, екземпляри та бекенди для QRMI

Виконуй кожну команду в терміналі на вхідному вузлі, якщо крок не вказує інакше.

Передумови​

  • Кластер Slurm з OpenMPI, PMIx і плагіном QRMI SPANK, які встановлює адміністратор кластера. Ці компоненти описано в таких посібниках:

    • Quantum resource management interface (QRMI)

    • Плагін SPANK для QRMI

    • Посібник користувача плагіна SPANK

  • Домашній каталог і робочий каталог, які вхідний вузол і обчислювальні вузли бачать за тими самими абсолютними шляхами

  • Вихідний доступ HTTPS до GitHub, PyPI, IBM Quantum і Prefect Cloud з вхідного вузла та до IBM Quantum з обчислювальних вузлів

  • Обліковий запис IBM Quantum Platform з ключем API IBM Cloud і принаймні одним екземпляром

  • Обліковий запис Prefect Cloud або сервер Prefect, який ти розміщуєш самостійно

  • Git, компілятори C і C++, CMake, BLAS, LAPACK і MPI на кластері для збірок розв'язувачів у навчальному матеріалі

примітка

У прикладах використовуються розділ Slurm normal і обчислювальні вузли c1 та c2. Заміни їх назвами зі свого кластера.

Крок 1: Увійди на вхідний вузол​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Крок 2: Установи uv​

Встанови менеджер пакетів uv і перевір установлення:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Крок 3: Задай шляхи й створи робочий каталог​

У цьому посібнику та в навчальних матеріалах використовуються дві змінні середовища:

ЗміннаПрикладПризначення
QCSC_PREFECT$HOME/qcsc-prefectКопія репозиторію qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectРобочий каталог завдань розв'язувача та завдань QRMI

Обидва шляхи мають бути на сховищі, яке обчислювальні вузли бачать за тим самим абсолютним шляхом. Якщо у твоєму кластері немає каталогу /shared, вибери інший спільний шлях.

Задай змінні та створи робочий каталог. Задавай змінні знову в кожній новій оболонці, перш ніж виконувати навчальний матеріал:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Щоб змінні задавалися автоматично в кожній новій оболонці, додай їх до ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Крок 4: Клонуй qcsc-prefect​

Клонуй репозиторій і перейди на тег випуску, наприклад v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Крок 5: Створи середовище робочого процесу​

Створи середовище робочого процесу з Python 3.12 та активуй його:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

Встанови пакети qcsc-prefect. Параметр --no-deps зберігає точні закріплені версії між пакетами копії репозиторію. Сам робочий процес установлюється в навчальному матеріалі:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Перевір, що команди доступні:

which prefect qcsc-qrmi

Активуй ~/venv/qcsc-host у кожній новій оболонці на вузлі входу.

Крок 6: Увійди в Prefect​

Увійди в Prefect Cloud. Вибери Paste an API key, встав API-ключ Prefect Cloud і вибери свій робочий простір:

prefect cloud login

Перевір з'єднання. У виводі показано PREFECT_API_URL і твій робочий простір:

prefect config view
Необов'язково: використай власний сервер Prefect

Пропусти цю примітку, якщо ти використовуєш Prefect Cloud. Щоб використовувати власний сервер Prefect замість Prefect Cloud, виконай інструкції з How to run and access a Prefect server on a Slurm login node і задай адресу свого сервера замість <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Крок 7: Збережи облікові дані IBM Quantum​

Виконай qcsc-qrmi login після входу в Prefect, оскільки ця команда зберігає блок qrmi-runtime:

qcsc-qrmi login

Відповідай на запити:

  1. Встав свій API-ключ IBM Cloud. Ключ не відображається.

  2. Натисни Enter, щоб використовувати всі екземпляри.

  3. Введи номер екземпляра за замовчуванням, 1 у наведеному нижче прикладі.

  4. Введи номер або назву бекенду за замовчуванням, 4 (ibm_kingston) у наведеному нижче прикладі.

Команда також виводить примітку про обчислювальні вузли та рядки [qrmi] для sqd_blocks.toml, які в прикладі пропущено (...). Рядки [qrmi] тобі не потрібні, оскільки робочий процес зчитує екземпляр і бекенд із блока qrmi-runtime.

Команда qcsc-qrmi має такі підкоманди:

КомандаПризначення
qcsc-qrmi loginЗберегти API-ключ, екземпляри та бекенди й зберегти блок
qcsc-qrmi refreshЗнову знайти екземпляри та бекенди за збереженим ключем
qcsc-qrmi listВивести екземпляри та бекенди без ключа
qcsc-qrmi checkПеревірити, що екземпляр блока може використовувати свій бекенд

Установи файл на обчислювальних вузлах​

Плагін SPANK зчитує qrmi_config.json на кожному обчислювальному вузлі за шляхом із plugstack.conf, зазвичай /etc/slurm/qrmi_config.json. Попроси адміністратора кластера встановити твій ~/.qiskit/qrmi_config.json за цим шляхом. Встановлюй його знову після кожного qcsc-qrmi login або qcsc-qrmi refresh.

Залиш Session Mode блока qrmi-runtime зі значенням batch, оскільки плагін SPANK отримує QPU в batch mode.

Крок 8: Створи середовище обчислювального вузла​

Воркер QRMI працює на обчислювальному вузлі у власному середовищі. Створи його з тієї самої копії репозиторію. Параметр --python залишає активним ~/venv/qcsc-host:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Пакет qrmi[ibm] надає команду task_runner. У навчальному матеріалі до цього середовища додається хук компіляції SQD, а ~/venv/qcsc-node/bin/python використовується як python_executable у sqd_blocks.toml.

Перевір збережені екземпляри та бекенди. Команда ніколи не виводить ключ:

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh

Перевір, що екземпляр за замовчуванням може використовувати бекенд за замовчуванням:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Перевір, що Slurm запускає завдання на обох обчислювальних вузлах, також з PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Перевір середовище обчислювального вузла та робочий каталог на обчислювальному вузлі. Перша команда нічого не виводить, якщо імпорти виконано успішно:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
