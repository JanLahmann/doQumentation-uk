Передумови​

У цьому навчальному посібнику показано, як використати SQOA Solver від JIJ, щоб розв'язати задачу про максимальну незалежну множину (MIS) з більшою кількістю двійкових змінних, ніж кубітів у вибраному QPU. Основні кроки: завантажити екземпляр MIS із Quantum Optimization Benchmarking Library (QOBLIB) [1], сформулювати його у формі квадратичної неспрямованої двійкової оптимізації (QUBO) за допомогою qiskit-addon-opt-mapper, надіслати до SQOA Solver для виконання на QPU від IBM® та перевірити повернений розв'язок.

Задача про максимальну незалежну множину​

Незалежна множина — це підмножина вузлів графа, в якій жодні два вибрані вузли не мають спільного ребра. Максимальна незалежна множина (MIS) — це незалежна множина з найбільшою можливою кількістю вузлів. Застосування MIS охоплюють планування, розподіл ресурсів і проєктування мереж.

MIS є NP-складною задачею. У вичерпному пошуку кожен додатковий вузол подвоює кількість підмножин для розгляду, тому такий підхід непрактичний навіть для графів помірного розміру. QOBLIB містить MIS як один зі своїх десяти класів задач, тож це корисний бенчмарк для оцінювання робочих процесів квантової оптимізації на реальному обладнанні.

Математичне формулювання​

Для заданого неорієнтованого графа G=(V,E)G = (V, E)G=(V,E) призначимо двійкову змінну xvx_vxv​ кожному вузлу vvv:

  • xv=1x_v = 1xv​=1, якщо вузол vvv вибрано.

  • xv=0x_v = 0xv​=0 otherwise.

Двійкове лінійне формулювання максимізує кількість вибраних вузлів, не допускаючи вибору обох кінців жодного ребра:

Цільова функція підраховує вибрані вузли. Разом обмеження на ребра гарантують, що вибрані вузли утворюють незалежну множину.

У цьому навчальному посібнику використовується двійкове формулювання без обмежень від QOBLIB, яке замінює обмеження на ребра квадратичними штрафами:

max⁡x∈{0,1}∣V∣∑v∈Vxv−2∑(v,w)∈Exvxw.\max_{x \in \{0,1\}^{|V|}} \quad \sum_{v \in V} x_v - 2 \sum_{(v,w) \in E} x_v x_w.x∈{0,1}∣V∣max​v∈V∑​xv​−2(v,w)∈E∑​xv​xw​.

Щоразу, коли вибрано обидва кінці ребра, другий доданок віднімає від цільової функції двійку. Цей штраф робить конфліктний вибір менш вигідним, ніж збереження лише одного з кінців. Отримана цільова функція є QUBO, що є вхідним форматом, який приймає SQOA Solver.

Навіщо використовувати SQOA Solver?​

Багато підходів квантової оптимізації призначають один кубіт кожній двійковій змінній, тому місткість квантового обладнання може прямо обмежувати розмір задачі. SQOA Solver поєднує кілька технік редукції та гібридних обчислень, щоб пом'якшити це обмеження:

  • Він може впоратися із задачами з більшою кількістю двійкових змінних, ніж кубітів у QPU. Presolve застосовує правила редукції, які можуть зафіксувати змінні та спростити решту QUBO, зберігаючи принаймні один оптимальний розв'язок. Емпірично presolve також може зробити решту QUBO розрідженішою, що допомагає кодуванню на основі QRAC, яке йде далі.

    Потім розв'язувач використовує кодування на основі QRAC, виведене з Quantum Random Access Optimization (QRAO) [3], щоб подати кілька змінних (до трьох) без прямої взаємодії в QUBO на одному кубіті.

    Редукції від presolve та кодування залежать від структури задачі. Наприклад, у цьому посібнику задача з 200 змінними використовує лише 67 кубітів.

  • Він може бути менш чутливим до апаратного шуму. Вибіркова квантова діагоналізація [4], [5] використовує QPU для вибірки бітових рядків, але виконує діагоналізацію класично. Це уникає повторних обчислень на QPU для оновлення варіаційних параметрів і може зменшити вплив шуму на робочий процес оптимізації.

  • Він автоматизує робочий процес від presolve до постобробки. Ти надаєш правильно відформатований екземпляр QUBO і вибираєш бекенд. Потім SQOA Solver виконує весь робочий процес автоматично. Він застосовує presolve, відображає класичні змінні на релаксовану квантову задачу, будує та транспілює схеми для семплювання, виконує квантове семплювання та класичну діагоналізацію, округлює й уточнює призначення, а також відновлює та оцінює класичний розв'язок.

SQOA Solver приймає задачу QUBO як словник коефіцієнтів у форматі кортеж-рядок, який використовують функції оптимізації IBM®. Визнач допоміжну функцію, що перетворює QUBO, повернений OptimizationProblemToQubo, на цей формат.

Конвертер завжди повертає задачу мінімізації, що відповідає тому, як SQOA Solver трактує задачу-словник. Ключі використовують індекси змінних QUBO, і кожна змінна отримує лінійний запис, навіть із нульовим коефіцієнтом, щоб повернений розв'язок охоплював усі змінні.

def to_problem_dict(qubo: OptimizationProblem) -> dict[str, float]:
    """Convert a QUBO from OptimizationProblemToQubo to the SQOA Solver dictionary format."""
    objective = qubo.objective
    payload = {"()": objective.constant}
    # Keep every variable in the problem, even with a zero linear coefficient.
    payload.update({f"({i},)": 0.0 for i in range(qubo.get_num_vars())})
    for i, coefficient in objective.linear.to_dict().items():
        payload[f"({i},)"] += coefficient
    for (i, j), coefficient in objective.quadratic.to_dict().items():
        # Fold a binary diagonal term x_i * x_i = x_i into the linear term.
        key = f"({i},)" if i == j else f"({i}, {j})"
        payload[key] = payload.get(key, 0.0) + coefficient
    return {key: float(value) for key, value in payload.items()}

Розуміння фреймворку SQOA​

Квантовий алгоритм оптимізації на основі семплювання з квантовою релаксацією (SQOA-QR) [2] поєднує Quantum Random Access Optimization (QRAO) із вибірковою квантовою діагоналізацією:

  1. Квантова релаксація та кодування: SQOA Solver перетворює QUBO на мінімізаційну цільову функцію Ізінга вигляду c+∑ihizi+∑i<jJijzizjc + \sum_i h_i z_i + \sum_{i<j} J_{ij} z_i z_jc+∑i​hi​zi​+∑i<j​Jij​zi​zj​, де zi∈{−1,+1}z_i \in \{-1, +1\}zi​∈{−1,+1}. Потім QRAO [3] відображає кожну спінову змінну на спостережувану Паулі. Для кодування (3,1)(3,1)(3,1)-QRAC, що використовується тут, релаксований гамільтоніан має вигляд

    H~=cI+∑ikihiPf(i)+∑i<jkikjJijPf(i)Pf(j),\widetilde{H} = cI + \sum_i \sqrt{k_i} h_i P_{f(i)} + \sum_{i<j} \sqrt{k_i k_j} J_{ij} P_{f(i)} P_{f(j)},H=cI+i∑​ki​​hi​Pf(i)​+i<j∑​ki​kj​​Jij​Pf(i)​Pf(j)​,

    де III — одиничний оператор, f(i)f(i)f(i) призначає змінну iii кубіту та одному з XXX, YYY або ZZZ, а ki∈{1,2,3}k_i \in \{1,2,3\}ki​∈{1,2,3} — кількість змінних, відображених на той самий кубіт, що й iii. Коли обидва відповідні кубіти містять по три змінні, лінійний і квадратичний масштабні множники стають відповідно 3\sqrt{3}3​ та 333.

    Змінним, що ділять кубіт, призначаються різні некомутівні спостережувані Паулі. Змінні, які взаємодіють у QUBO, лишаються на різних кубітах, тоді як змінні без прямої взаємодії в QUBO можуть ділити кубіт. Тому зменшення кількості кубітів залежить від структури задачі.

  2. Квантове семплювання: Квантовий процесор вибирає бітові рядки зі схем, розроблених для дослідження низькоенергетичних станів релаксованого гамільтоніана.

  3. Вибіркова діагоналізація: Розв'язувач проєктує релаксований гамільтоніан на підпростір, натягнутий на базисні стани, отримані з вибраних бітових рядків, і класично діагоналізує спроєктований гамільтоніан [4], [5]. Для фіксованого набору вибраних бітових рядків нехай Sr\mathcal{S}_rSr​ — підпростір, натягнутий на rrr різних базисних станів, тож dim⁡(Sr)≤r\dim(\mathcal{S}_r) \leq rdim(Sr​)≤r. Його оцінена енергія основного стану дорівнює:

    Er=min⁡∣ψ⟩∈Sr⟨ψ∣ψ⟩=1⟨ψ∣H~∣ψ⟩,Sr⊆Sr′⟹Eexact≤Er′≤Er(r′≥r),E_r = \min_{\substack{|\psi\rangle \in \mathcal{S}_r \\ \langle\psi|\psi\rangle=1}} \langle\psi|\widetilde{H}|\psi\rangle, \qquad \mathcal{S}_r \subseteq \mathcal{S}_{r'} \Longrightarrow E_{\mathrm{exact}} \leq E_{r'} \leq E_r \quad (r' \geq r),Er​=∣ψ⟩∈Sr​⟨ψ∣ψ⟩=1​min​⟨ψ∣H∣ψ⟩,Sr​⊆Sr′​⟹Eexact​≤Er′​≤Er​(r′≥r),

    де EexactE_{\mathrm{exact}}Eexact​ — енергія основного стану повного релаксованого гамільтоніана. Отже, більший збережений підпростір не може збільшити оцінену енергію основного стану.

    Цей порядок припускає той самий результат семплювання і стосується енергії релаксованого гамільтоніана до округлення. Він теоретично не гарантує кращого поверненого класичного розв'язку. Однак у QRAO евристично очікується, що стан з нижчою енергією дасть кращий класичний розв'язок.

  4. Округлення: Релаксований стан, отриманий із діагоналізації, перетворюється на класичне двійкове призначення.

SQOA Solver оточує цей фреймворк класичною обробкою. Перед квантовим відображенням presolve застосовує правила редукції, які можуть зафіксувати змінні та спростити решту QUBO, зберігаючи принаймні один оптимальний розв'язок. Після діагоналізації та округлення класичний локальний пошук уточнює призначення, а OMMX відновлює та оцінює повний розв'язок.

Завантаження екземпляра​

QOBLIB розповсюджує кожен екземпляр MIS як граф у форматі DIMACS .gph, рядковому форматі, де рядок, що починається з p, задає кількість вузлів і ребер, а кожен рядок, що починається з e, визначає ребро.

QOBLIB також публікує оптимальний або найкращий відомий еталонний розв'язок для кожного екземпляра. Наведені нижче функції завантажують обидва з репозиторію QOBLIB. DIMACS нумерує вузли з 1, тому граф перенумеровується, щоб починатися з 0.

Якщо ти хочеш почати зі свого власного графа, пропусти завантаження та сформулюй задачу зі свого графа NetworkX так само.

QOBLIB_URL = "https://raw.githubusercontent.com/ZIB-AOPT/QOBLIB/refs/heads/main/07-independentset"

def fetch_qoblib_graph(name: str) -> nx.Graph:
    """Download a QOBLIB independent-set instance as a NetworkX graph."""
    with urllib.request.urlopen(
        f"{QOBLIB_URL}/instances/{name}.gph"
    ) as response:
        lines = response.read().decode().splitlines()
    graph = nx.Graph()
    for fields in map(str.split, lines):
        if fields and fields[0] == "p":
            # Header: p edge <number of nodes> <number of edges>
            graph.add_nodes_from(range(int(fields[2])))
        elif fields and fields[0] == "e":
            # DIMACS labels nodes from 1; relabel them to start from 0.
            graph.add_edge(int(fields[1]) - 1, int(fields[2]) - 1)
    return graph

def fetch_reference_objective(name: str) -> float:
    """Read the objective value of the QOBLIB reference solution."""
    with urllib.request.urlopen(
        f"{QOBLIB_URL}/solutions/{name}.opt.sol"
    ) as response:
        for line in response.read().decode().splitlines():
            if line.startswith("# Objective value"):
                return float(line.split("=")[1])
    raise ValueError(f"No objective value found for {name}.")

Формулювання QUBO​

Побудуй двійкове лінійне формулювання з розділу «Передумови» як OptimizationProblem з однією двійковою змінною на вузол, цільовою функцією, що підраховує вибрані вузли, та одним обмеженням на ребро. Потім перетвори його за допомогою OptimizationProblemToQubo.

З вагою штрафу 2 конвертер замінює кожне обмеження на ребро штрафним доданком 2xvxw2 x_v x_w2xv​xw​ і перетворює максимізацію на мінімізацію, тож перетворена задача є двійковим формулюванням без обмежень від QOBLIB зі зміненим знаком. Індекси змінних QUBO — це мітки вузлів графа. Клас застосування IndependentSet у qiskit_addon_opt_mapper.applications будує ту саму модель з обмеженнями за допомогою IndependentSet(G).to_optimization_problem().

Крок 2: Оптимізація задачі для виконання на квантовому обладнанні​

SQOA Solver виконує квантове відображення та підготовку до виконання на обладнанні всередині функції. Спершу він застосовує presolve до QUBO, потім відображає решту змінних на релаксований гамільтоніан за допомогою кодування на основі QRAC.

Для квантового семплювання він будує схеми на основі релаксованого гамільтоніана та транспілює їх для вибраного бекенда. Зменшення розміру задачі та кількості кубітів завдяки presolve і кодуванню залежить від задачі, тому налаштовуй розв'язувач, не припускаючи фіксованого коефіцієнта редукції.

Налаштування вхідних даних розв'язувача​

SQOA Solver вимагає двох вхідних даних:

  • problem, словник із кроку 1.

  • variable_type, що дорівнює "binary" для цього QUBO.

Він також приймає два необов'язкові вхідні дані:

  • backend_name вибирає QPU. Якщо його пропущено або він дорівнює None, функція вибирає найменш завантажений робочий QPU, доступний твоєму екземпляру.

  • options — це словник, що керує бюджетом семплювання (shots), класичним початковим значенням (seed), використанням сесії (session), класичним локальним пошуком (postprocessing_level) та тегами завдань (job_tags). Якщо збільшити shots, статистика семплювання може покращитися.

Аргумент function_size ("S", "M" або "L") вибирає обчислювальні ресурси для завдання й передається безпосередньо в solver.run(), поза options. Обчисли його за задачею перед надсиланням, як показано в наступному розділі.

Усі вхідні дані, їхні типові значення та правила валідації дивись у довіднику API.

У цьому посібнику бекенд задається явно, використовуються типові значення для shots, session та postprocessing_level і задається класичне початкове значення. Збери вхідні дані в словник, щоб передати їх у solver.run() на кроці 3.

Обчисли розмір функції​

Розмір функції залежить від кількості змінних у QUBO та від його щільності — частки пар змінних, що взаємодіють. Критерії для кожного розміру дивись у розділі Function sizes посібника SQOA Solver. Наведений нижче калькулятор виконує те саме обчислення, що й функція, не надсилаючи завдання.

# Calculate the function size a problem needs, before submitting it.
# calculate_function_size(problem) returns "S", "M", or "L" and submits
# nothing. The size comes from the number of variables and how densely
# they interact.

from collections.abc import Iterator
from itertools import combinations
from typing import Any, Literal

from qiskit_addon_opt_mapper.problems import OptimizationProblem

Size = Literal["S", "M", "L"]
_ORDER = {"S": 0, "M": 1, "L": 2}

# Limits are provided by IBM
_SMALL_NUMVARS, _SMALL_DENSITY = 50, 0.1
_MEDIUM_NUMVARS, _MEDIUM_DENSITY = 100, 0.25

def calculate_function_size(problem: Any, **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") needed to run ``problem``."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def to_optimization_problem(problem: Any) -> OptimizationProblem:
    """Convert SQOA input into an ``OptimizationProblem``.

    Accept an OMMX ``Instance`` directly, or a dictionary containing a coefficient
    dictionary as ``problem`` and ``"binary"`` or ``"spin"`` as ``variable_type``.
    Convert to a binary minimization problem with consecutive variable IDs from zero.
    Leave the input instance unchanged.
    Return an existing ``OptimizationProblem`` unchanged.
    """
    if isinstance(problem, OptimizationProblem):
        return problem
    import ast
    import math
    import re

    from ommx.v1 import DecisionVariable, Instance, Kind

    _TERM_ID = r"(?:0|[1-9][0-9]*)"
    _TERM_SPACE = r"[ \t\r\n]*"
    _TERM_KEY_PATTERN = (
        rf"^\({_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE},"
        rf"{_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE}(?:,{_TERM_SPACE})?)?)?\)(?![\s\S])"
    )

    def _term_ids(key: str) -> tuple[int, ...]:
        if (
            not isinstance(key, str)
            or re.fullmatch(_TERM_KEY_PATTERN, key) is None
        ):
            raise ValueError("invalid term key")
        ids = ast.literal_eval(key)
        if len(set(ids)) != len(ids):
            raise ValueError("repeated variable ID")
        return tuple(sorted(ids))

    def _dictionary_to_instance(
        problem: dict[str, object], variable_type: str
    ) -> Instance:
        terms: dict[tuple[int, ...], float] = {}
        variable_ids: set[int] = set()
        for key, value in problem.items():
            ids = _term_ids(key)
            if type(value) not in (int, float):
                raise ValueError("invalid coefficient")
            coefficient = float(value)
            if not math.isfinite(coefficient):
                raise ValueError("invalid coefficient")
            variable_ids.update(ids)
            terms[ids] = terms.get(ids, 0.0) + coefficient
            if not math.isfinite(terms[ids]):
                raise ValueError("coefficient overflow")
        variables = {
            i: DecisionVariable.binary(i) for i in sorted(variable_ids)
        }
        expressions = {
            i: 1 - 2 * variable if variable_type == "spin" else variable
            for i, variable in variables.items()
        }
        objective = 0.0
        for ids, coefficient in terms.items():
            term = coefficient
            for i in ids:
                term = term * expressions[i]
            objective = objective + term
        return Instance.from_components(
            decision_variables=list(variables.values()),
            objective=objective,
            constraints=[],
            sense=Instance.MINIMIZE,
        )

    if isinstance(problem, Instance):
        instance = problem
    else:
        if (
            not isinstance(problem, dict)
            or not {"problem", "variable_type"} <= problem.keys()
        ):
            raise ValueError(
                "SQOA sizing requires an OMMX Instance or a coefficient input envelope "
                "with 'problem' and 'variable_type'"
            )
        variable_type = problem["variable_type"]
        if variable_type not in ("binary", "spin"):
            raise ValueError("variable_type must be binary or spin")
        if not isinstance(problem["problem"], dict):
            raise ValueError(
                "problem must be a coefficient dictionary; pass OMMX Instances directly"
            )
        instance = _dictionary_to_instance(problem["problem"], variable_type)

    variables = list(instance.decision_variables)
    degree = instance.objective.degree()
    if not variables:
        raise ValueError(
            "problem must contain at least one decision variable"
        )
    if any(variable.kind == Kind.Continuous for variable in variables):
        raise ValueError(
            "problem must not contain Continuous decision variables"
        )
    if degree > 2:
        raise ValueError("problem objective degree must be at most two")
    # Copy the instance so minimization does not modify the caller's original.
    normalized = Instance.from_bytes(instance.to_bytes())
    normalized.as_minimization_problem()
    qubo, offset = normalized.as_qubo_format()
    if not math.isfinite(offset) or any(
        not math.isfinite(v) for v in qubo.values()
    ):
        raise ValueError("problem objective coefficients must all be finite")

    ids = [variable.id for variable in variables]
    dense_ids = {
        variable_id: index for index, variable_id in enumerate(sorted(ids))
    }
    linear = {}
    quadratic = {}
    for (first, second), coefficient in qubo.items():
        i, j = dense_ids[first], dense_ids[second]
        if i == j:
            linear[i] = linear.get(i, 0.0) + coefficient
        else:
            pair = (min(i, j), max(i, j))
            quadratic[pair] = quadratic.get(pair, 0.0) + coefficient

    model = OptimizationProblem()
    model.binary_var_list(len(ids), name="x")
    model.minimize(
        constant=offset,
        linear=linear,
        quadratic=quadratic,
    )
    return model

def _measure(problem: Any, **kwargs: Any) -> dict[str, float]:
    """Return the number of variables and the interaction density."""
    model = to_optimization_problem(problem)
    num_vars = model.get_num_vars()

    pairs = set()
    for term in _interactions(model):
        pairs.update(frozenset(pair) for pair in combinations(set(term), 2))

    max_pairs = num_vars * (num_vars - 1) // 2
    return {
        "num_vars": num_vars,
        "density": len(pairs) / max_pairs if max_pairs else 0.0,
    }

def _interactions(problem: OptimizationProblem) -> Iterator[tuple[int, ...]]:
    """Yield the variables of every term that couples two or more of them.

    A constraint contributes every variable in it, because on hardware it becomes
    a penalty whose square couples them all.
    """
    objective = problem.objective
    yield from objective.quadratic.to_dict()
    for expression in objective.higher_order.values():
        yield from expression.to_dict()

    for constraint in problem.linear_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.quadratic_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.higher_order_constraints:
        yield _constraint_support(constraint)

def _constraint_support(constraint: Any) -> tuple[int, ...]:
    """Return every variable appearing in a constraint's left-hand side."""
    variables = set(constraint.linear.to_dict())
    if hasattr(constraint, "quadratic"):
        for term in constraint.quadratic.to_dict():
            variables.update(term)
    if hasattr(constraint, "higher_order"):
        for expression in constraint.higher_order.values():
            for term in expression.to_dict():
                variables.update(term)
    return tuple(variables)

def _is_small(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["num_vars"] <= _SMALL_NUMVARS
        and metrics["density"] <= _SMALL_DENSITY
    )

def _is_medium(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return (
        metrics["num_vars"] <= _MEDIUM_NUMVARS
        and metrics["density"] <= _MEDIUM_DENSITY
    )

    print("The classical local search did not run for this problem.")
else:
    x_before = [before[f"x_{i}"] for i in range(qubo.get_num_vars())]
    changed = sum(
        before[key] != value for key, value in result["solution"].items()
    )
    print(
        f"Objective before local search: {qubo.objective.evaluate(x_before)}"
    )
    print(f"Objective after local search: {result['objective_value']}")
    print(f"Variables changed by local search: {changed}")
Objective before local search: -12.0
Objective after local search: -35.0
Variables changed by local search: 19

Перевір обмеження незалежності​

Оскільки QUBO подає суміжність через штрафні члени, а не явні обмеження, евристичний результат усе ще може містити суміжні вузли. Перевір повернуті вузли безпосередньо за графом. Для порівняння та візуалізації в наступних розділах скопіюй повернуту множину та жадібно видали один кінець кожного виявленого конфлікту.

returned_set = set(selected_nodes)
conflicts = [
    (u, v) for u, v in G.edges if u in returned_set and v in returned_set
]
print(f"Conflicting edges in the returned set: {len(conflicts)}")

independent_set = returned_set.copy()
for u, v in conflicts:
    if u in independent_set and v in independent_set:
        # Drop the endpoint that has more selected neighbors.
        drop = max(
            (u, v),
            key=lambda node: sum(nb in independent_set for nb in G[node]),
        )
        independent_set.remove(drop)

assert all(
    not (u in independent_set and v in independent_set) for u, v in G.edges
)
print(f"Independent set size after repair: {len(independent_set)}")
Conflicting edges in the returned set: 0
Independent set size after repair: 35

Порівняй з еталонним розв'язком​

На кроці 1 ти завантажив(-ла) цільове значення еталонного розв'язку QOBLIB. Еталонні розв'язки QOBLIB можуть бути оптимальними або найкращими з відомих, тому порівнюй з еталонним цільовим значенням, не припускаючи, що воно завжди є сертифікованим оптимумом.

Для цієї задачі максимізації відношення 1,0 означає, що виправлений результат збігається з еталонним цільовим значенням.

ratio_to_reference = len(independent_set) / reference_objective

print(f"Reference objective: {reference_objective:g}")
print(f"Ratio to reference: {ratio_to_reference:.3f}")
Reference objective: 44
Ratio to reference: 0.795

Висновок​

У цьому навчальному посібнику ти завантажив(-ла) екземпляр MIS із QOBLIB, сформулював(-ла) його як QUBO за допомогою qiskit-addon-opt-mapper, підключився(-лась) до SQOA Solver, налаштував(-ла) та подав(-ла) навантаження, відобразив(-ла) повернуте присвоєння назад на граф і перевірив(-ла) вибрані вузли за вихідним графом.

Ти також порівняв(-ла) результат з еталонним розв'язком QOBLIB, дослідив(-ла) внесок класичної постобробки та перевірив(-ла) використання ресурсів кожною фазою виконання.

SQOA Solver поєднує presolve, QRAO з кодуванням на основі QRAC, побудову семплувальних кіл, транспіляцію з урахуванням апаратури, діагоналізацію на основі семплів, округлення та класичне уточнення. Цей робочий процес може відобразити більше бінарних змінних, ніж дозволило б кодування «одна змінна на кубіт». Обсяг скорочення завдяки presolve та кодуванню залежить від структури задачі, а якість розв'язку — від отриманих семплів.

Параметри shots та postprocessing_level керують відповідно бюджетом квантового семплування та класичним уточненням, не змінюючи робочого процесу подання.

Додаток: подай задачу як екземпляр OMMX​

SQOA Solver також приймає ommx.v1.Instance із SDK OMMX. Пакет OMMX Quantum Benchmarks розповсюджує задачі QOBLIB як екземпляри OMMX разом з їхніми еталонними розв'язками, тож ти можеш завантажити ту саму QUBO, не формулюючи її самостійно.

З вхідними даними OMMX objective_value обчислюється в розумінні екземпляра, а результат також містить канонічний ommx.v1.Solution. Встанови пакет, який також встановлює SDK OMMX:

# %pip install ommx-quantum-benchmarks

Завантаж модель binary_unconstrained того самого екземпляра. Завантажувач наборів даних друкує повідомлення про перебіг, тому код перехоплює їх, щоб вивід був компактним.

%%capture
from ommx_quantum_benchmarks.qoblib import IndependentSet

ommx_instance, _ = IndependentSet()("binary_unconstrained", INSTANCE_NAME)

SQOA Solver отримує екземпляр OMMX як стандартний рядок Base64 із доповненням і повертає канонічний розв'язок у тому самому форматі. Визнач дві допоміжні функції для цього перетворення:

  • to_problem_payload() серіалізує ommx.v1.Instance у рядок, який ти передаєш як problem.

  • to_ommx_solution() декодує канонічний ommx.v1.Solution з результату.

import base64

from ommx.v1 import Instance, Solution

def to_problem_payload(instance: Instance) -> str:
    """Serialize an OMMX instance into the `problem` string for SQOA Solver."""
    return base64.b64encode(instance.to_bytes()).decode()

def to_ommx_solution(result: dict) -> Solution:
    """Decode the canonical OMMX solution from a SQOA Solver result."""
    payload = result["metadata"]["solver_info"]["ommx_solution"]
    return Solution.from_bytes(base64.b64decode(payload, validate=True))

Подай екземпляр з тими самими вхідними даними, що й раніше, замінивши лише problem. Потім декодуй канонічний розв'язок і прочитай вибрані вузли за іменами змінних.

ommx_job = solver.run(
    **{**sqoa_input, "problem": to_problem_payload(ommx_instance)},
    function_size=size,
)
ommx_result = ommx_job.result()

ommx_solution = to_ommx_solution(ommx_result)
x_values = ommx_solution.extract_decision_variables("x")
ommx_nodes = sorted(
    node for (node,), value in x_values.items() if value > 0.5
)

print(f"Objective value: {ommx_result['objective_value']}")
print(f"Selected nodes: {len(ommx_nodes)}")

Selected nodes: 35
