Класифікація кредитного ризику за допомогою Quantum Feature Extraction від Rimay компанії Kipu Quantum

примітка

IBM Quantum® Functions — це бета-функція, доступна лише користувачам планів IBM Quantum Premium Plan, Flex Plan і On-Prem (через IBM Quantum Platform API) Plan. Бета-функції можуть змінюватися.

Оцінка використання: 2 хвилини на процесорі Nighthawk r2. (ПРИМІТКА: це лише оцінка. Фактичний час виконання може відрізнятися.)

Результати навчання​

  • Підготувати табличні дані з категоріальними та числовими стовпцями для квантової функції Rimay.

  • Підігнати квантове відображення ознак на навчальних даних і відобразити тестові дані в тому самому запуску.

  • Навчити класичні моделі на квантово-перетворених ознаках — окремо та разом з оригінальними ознаками.

  • Порівняти результати з суто класичною базовою лінією.

Передісторія​

Багато задач машинного навчання в індустрії мають справу з малими або середніми табличними наборами даних, де додавання даних неможливе, а точність моделі виходить на плато. Типовий приклад — кредитний скоринг. Кредитор використовує кілька десятків атрибутів, щоб вирішити, чи ймовірно, що заявник поверне кредит.

Rimay від Kipu Quantum додає до такого конвеєра крок квантової передобробки. Вона реалізує алгоритм оцифрованого контрдіабатичного квантового вилучення ознак [1]. Кожна вхідна ознака відображається на один кубіт. Значення ознак і взаємна інформація між ознаками задають локальні поля та зв'язки гамільтоніана спінового скла. Контрдіабатична динаміка потім еволюціонує квантову систему до її низькоенергетичних станів, а одно- та двочастинкові середні значення, виміряні наприкінці, стають новими, квантово-перетвореними ознаками. Ці ознаки відображають нелінійні кореляції між входами, і ти можеш подати їх у будь-яку класичну модель.

Цей посібник використовує німецький кредитний набір даних з OpenML [2], з 1000 заявників і 20 атрибутами, щоб навчити класифікатор випадкового лісу. Спочатку ти встановлюєш класичну базову лінію, потім надсилаєш дані до Rimay і, нарешті, навчаєш модель того самого типу на квантово-перетворених ознаках — окремо та разом з оригінальними ознаками.

def train_random_forest(x, y, n_estimators, max_depth):
    """Train a random forest classifier with fixed hyperparameters."""
    model = RandomForestClassifier(
        n_estimators=n_estimators,
        max_depth=max_depth,
        min_samples_split=5,
        min_samples_leaf=1,
        max_features="sqrt",
        random_state=42,
        n_jobs=-1,
    )
    return model.fit(x, y)

def evaluate(model, x, y):
    """Return the classification metrics of a trained model on a test set."""
    y_pred = model.predict(x)
    y_proba = model.predict_proba(x)[:, 1]
    return {
        "Accuracy": accuracy_score(y, y_pred),
        "AUC": roc_auc_score(y, y_proba),
        "F1 score": f1_score(y, y_pred),
        "Precision": precision_score(y, y_pred),
        "Recall": recall_score(y, y_pred),
    }

Крок 2: Оптимізуй задачу для виконання на квантовому обладнанні​

Rimay будує та транспілює схеми для процесора, який ти вибираєш, тому оптимізувати схему вручну не потрібно. Вкажи кількість шотів на схему в межах таких обмежень:

  • Кожна ознака потребує одного кубіта, тому процесор повинен мати щонайменше стільки кубітів, скільки ознак у наборі даних.

  • Rimay виконує одну схему на рядок, навчальні та тестові рядки разом. Одне завдання може запросити щонайбільше 10 мільйонів виконань, тому кількість рядків, помножена на shots, має вкладатися в цей бюджет.

Обчислення розміру функції​

Кожне завдання виконується з розміром функції S, M або L, який визначає обчислювальні ресурси, на яких воно працює. Для Rimay розмір залежить від кількості рядків, які відображає завдання, навчальних і тестових разом. Якщо ти запитаєш замалий розмір, завдання завершиться помилкою 4600. Розміри та їхні обмеження описано в розділі Function sizes посібника з Rimay.

Наступна комірка визначає калькулятор розміру. Він виконується на твоїй машині, читає лише дані, які ти йому передаєш, і нічого не подає.

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

Передай набори даних у тому ж порядку, що й файли в input_file, разом з режимом запуску:

    [x_train, y_train, x_test], mode="fit-transform"
)

Перевіряй статус завдання, поки воно виконується. job.result() блокує виконання, доки завдання не завершиться.

Результат містить mapping_id, який ідентифікує відображення, підігнане цим запуском. У цьому посібнику він тобі не потрібен, оскільки тестову вибірку було відображено в тому самому запуску. Збережи цей ID, якщо хочеш пізніше відображати нові рядки за допомогою mode="transform". Це єдиний спосіб отримати доступ до підігнаного відображення, а без нього тобі доведеться підганяти та оплачувати нове. Відображення побудоване для розташування кубітів цього процесора, тому наступний запуск transform має передати той самий backend_name.

mapping_id = result["mapping_id"]

Крок 4: Постобробка та повернення результату в потрібному класичному форматі​

Завантаження квантово-перетворених ознак​

Завантаж файли, які записало завдання, використовуючи імена з output_files. Кожне ім'я починається з ID завдання, тож файли цього запуску залишаються доступними після наступних запусків. Передай target_name, щоб кожен файл зберігався під власним іменем.

train_file, test_file = result["output_files"]
for file_name in (train_file, test_file):
    catalog.file_download(file_name, rimay, target_name=file_name)

xq_train = pd.read_csv(train_file).to_numpy()
xq_test = pd.read_csv(test_file).to_numpy()

Навчання на квантово-перетворених ознаках​

Навчи випадковий ліс лише на квантово-перетворених ознаках.

quantum = train_random_forest(
    xq_train, y_train, n_estimators=900, max_depth=15
)
results["Quantum"] = evaluate(quantum, xq_test, y_test)

Навчання на об'єднаних класичних і квантових ознаках​

Об'єднай оригінальні та квантово-перетворені ознаки в стек і навчи ту саму модель на цій комбінації.

xh_train = np.hstack([x_train.to_numpy(), xq_train])
xh_test = np.hstack([x_test.to_numpy(), xq_test])

hybrid = train_random_forest(
    xh_train, y_train, n_estimators=900, max_depth=15
)
results["Hybrid"] = evaluate(hybrid, xh_test, y_test)

AUC вимірює, наскільки добре модель ранжує хороші кредити вище за погані, незалежно від порогу рішення, що робить його найінформативнішою метрикою на цьому незбалансованому наборі даних (70% хороших кредитів). У бенчмарках Kipu Quantum квантово-перетворені ознаки самі по собі досягли AUC, подібного до класичної базової лінії, а гібридна модель, що поєднує обидва типи, досягла найвищих AUC та F1-міри. Отже, квантово-перетворені ознаки додають інформацію, якої класичні ознаки самі по собі не дають.

Висновок​

Чого ти досяг​

У цьому посібнику ти зробив таке:

  1. Підготував реальний набір даних про кредитний ризик з категоріальними та числовими атрибутами для квантового вилучення ознак.

  2. Встановив класичну базову лінію на основі випадкового лісу.

  3. Використав Rimay, щоб підігнати квантове відображення ознак на квантовому обладнанні та відобразити навчальну й тестову вибірки за один запуск.

  4. Навчив ту саму модель на квантово-перетворених і на об'єднаних ознаках та порівняв їх з базовою лінією.

Ключові висновки​

  • Rimay вбудовується в наявний конвеєр машинного навчання як один додатковий крок передобробки. Ти зберігаєш свою підготовку даних і свою класичну модель.

  • Кількість кубітів обмежує кількість вхідних ознак, а кількість рядків, помножена на shots, обмежує розмір одного завдання.

  • Використовуй квантово-перетворені ознаки разом з оригінальними як типовий варіант, оскільки модель може використати обидва типи.

Наступні кроки​

Рекомендації
  • Прочитай посібник з Rimay, щоб дізнатися про всі входи, відображати нові дані за допомогою mode="transform" і побачити додаткові бенчмарки.
  • Прочитай, як квантове вилучення ознак застосували до класифікації супутникових зображень [3].
